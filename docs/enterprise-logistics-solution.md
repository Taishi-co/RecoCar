# 大客户仓储物流无人车配送平台方案

## 一、方案概述

### 业务背景

**客户定位**：
- 有仓储物流业务的企业（如电商仓储、批发商、供应链企业）
- 拥有自有车辆（5-50辆）
- 有稳定的内部配送需求
- 希望提高效率、降低成本

**核心需求**：
1. **一车多装**：一辆车装载多个订单
2. **多装多卸**：多个取货点、多个送货点
3. **路径优化**：自动规划最优配送路线
4. **自有车辆对外服务**：闲置车辆接外部订单
5. **车辆转租**：将车辆转租给其他运力方
6. **发布外部需求**：自有运力不足时，让外部运力方接单

### 平台定位

**企业版 vs 公共版**：

| 功能 | 企业版 | 公共版 |
|------|--------|--------|
| 用户角色 | 企业内部人员、外部运力 | 需求方、运力方 |
| 车辆来源 | 自有车辆 + 外部车辆 | 运力方车辆 |
| 订单来源 | 内部订单 + 外部订单 | 公共订单 |
| 订单类型 | 批量配送、单件配送 | 单件配送为主 |
| 路径优化 | 多点路径优化（20+点） | 少量路径优化（<10点） |
| 结算方式 | 企业内部结算 + 外部结算 | 单一结算 |
| 数据隔离 | 企业数据独立 | 数据共享 |

### 2. 多租户架构

**数据隔离策略**：

```
企业A的数据  →  数据库Schema A（或TenantID=A）
企业B的数据  →  数据库Schema B（或TenantID=B）
公共订单数据  →  公共Schema（或TenantID=public）
```

**隔离原则**：
- 企业内部订单：仅企业内部可见
- 企业对外需求：发布到公共平台
- 外部订单：企业可查看已接订单
- 车辆转租：转租期间车辆数据隔离

## 四、核心业务场景

### 场景1：企业内部批量配送

#### 业务背景

**适用场景**：
- 仓库配送到多个门店
- 批发商配送到多个客户
- 企业内部多点配送

**特点**：
- 同一取货点（仓库）
- 多个送货点（分散）
- 使用自有车辆
- 批量订单

#### 业务流程

```
企业管理员/调度员发布内部批量配送需求
  ↓
填写统一取货点信息
  ├─ 取货地址：XX仓库
  ├─ 联系人：仓库管理员
  └─ 联系电话：138****1234
  ↓
添加多个送货点
  ├─ 送货点1：门店A，地址XXX，电话XXX
  ├─ 送货点2：门店B，地址XXX，电话XXX
  └─ ...（可添加20-50个送货点）
  ↓
填写每个送货点的货物信息
  ├─ 门店A：10件空调，每件65kg
  └─ 门店B：15件冰箱，每件80kg
  ↓
选择配送时间窗
  ├─ 期望配送时间：明天
  └─ 时间段：9:00-12:00
  ↓

  ├─ 总重量：3500kg
  ├─ 总体积：18m³
  └─ 建议车辆：大型车×3辆
  ↓
提交需求，进入待调度
  ↓
调度员查看待调度需求
  ↓
选择派车方案
  ├─ 方案1：3辆车，每辆车10-15个点
  ├─ 方案2：2辆车，每辆车20-25个点
  └─ 方案3：系统自动分配
  ↓
确认派车方案
  ↓
系统自动路径优化
  ↓
生成每辆车的配送路线
  ↓
车辆1：A1→A2→...→A15（15个点）
  ↓
车辆2：A16→A17→...→A30（15个点）
  ↓
车辆3：A31→A32→...→A50（20个点）
  ↓
调度员确认路线
  ↓
分配司机
  ↓
司机接收任务
  ↓
开始配送
  ↓
逐个送货点配送
  ↓
配送完成
  ↓
企业内部结算（如需要）
```

#### 路径优化算法

**问题定义**：
- 1个取货点P
- n个送货点D1, D2, ..., Dn（n=20-50）
- m辆车V1, V2, ..., Vm
- 每辆车载重C，容积V
- 找到最优车辆分配和路径

**算法选择**：
- n ≤ 30：遗传算法
- 30 < n ≤ 50：聚类+遗传算法
- n > 50：聚类+贪心算法

**优化目标**：
- 总行驶距离最短
- 总配送时间最短
- 车辆负载均衡
- 满足时间窗

**约束条件**：
- 先取货后送货
- 车辆载重限制
- 车辆容积限制
- 时间窗限制

### 场景2：自有车辆接外部订单

#### 业务背景

**适用场景**：
- 企业自有车辆闲置
- 车辆利用率不足
- 希望增加收入

**特点**：
- 自有车辆进入公共接单大厅
- 接外部订单
- 收入归企业
- 不影响企业内部优先级

#### 业务流程

```
企业管理员查看车辆状态
  ↓
发现车辆A-001、A-002闲置
  ↓
企业管理员将车辆设置为"对外服务"状态
  ↓
车辆进入公共接单大厅
  ↓
外部运力方（或平台用户）看到车辆信息
  ↓
外部需求方发布订单
  ↓
平台智能匹配
  ↓
推荐给车辆A-001
  ↓
司机（或管理员）查看推荐
  ↓
选择接单
  ↓
洽谈运费
  ↓
确认接单
  ↓
系统路径优化
  ↓
开始配送
  ↓
配送完成
  ↓
结算到企业账户
  ↓
企业管理员查看收益
```

#### 车辆状态管理

**车辆状态**：

| 状态 | 说明 | 可接订单 |
|------|------|----------|
| 空闲-内部 | 闲置，仅接企业内部订单 | 内部订单 |
| 空闲-对外 | 闲置，可接外部订单 | 内部+外部订单 |
| 执行-内部 | 正在执行企业内部订单 | 不可接单 |
| 执行-对外 | 正在执行外部订单 | 不可接单 |
| 转租中 | 车辆已转租 | 不可接单 |
| 维修中 | 车辆维修中 | 不可接单 |

**状态切换**：

```
空闲-内部 → 空闲-对外：企业管理员切换
空闲-对外 → 空闲-内部：企业管理员切换
空闲-对外 → 执行-对外：接单后自动切换
执行-对外 → 空闲-对外：配送完成后自动切换
空闲-内部 → 执行-内部：接内部订单后自动切换
执行-内部 → 空闲-内部：配送完成后自动切换
空闲-对外 → 转租中：转租时切换
转租中 → 空闲-内部：转租结束后切换
```

## 五、路径优化算法设计

### 1. 企业内部批量配送优化

**问题定义**：
- 1个取货点P
- n个送货点D1, D2, ..., Dn
- m辆车V1, V2, ..., Vm
- 找到最优车辆分配和路径

**算法流程**：

```
步骤1：聚类分组
  - 使用K-means算法，将送货点聚类为m组
  - 每组分配一辆车
  - 确保每组的总重量和总体积不超过车辆限制

步骤2：组内路径优化
  - 对每组使用遗传算法
  - 找到组内最优路径
  - 优化目标：最短距离 + 满足时间窗

步骤3：负载均衡
  - 检查各组的负载是否均衡
  - 如不均衡，调整分组
  - 重复步骤1-2

步骤4：最终优化
  - 使用模拟退火算法微调
  - 全局寻优
  - 输出最优方案
```

**性能要求**：
- n ≤ 30：<3秒
- 30 < n ≤ 50：<5秒
- n > 50：<10秒

### 2. 外部订单合并优化

**问题定义**：
- 运力方已有订单
- 新订单与现有订单可合并
- 找到最优路径

**算法流程**：

```
步骤1：可行性检查
  - 检查位置是否顺路
  - 检查载重是否充足
  - 检查时间是否兼容

步骤2：路径插入
  - 计算新订单在现有路径中的最优插入位置
  - 评估插入后的收益
  - 选择收益最大的位置

步骤3：路径优化
  - 使用局部搜索优化路径
  - 输出最优路径

步骤4：收益计算
  - 计算总收益
  - 计算每公里收益
  - 判断是否值得接单
```

**性能要求**：
- 响应时间：<500ms
