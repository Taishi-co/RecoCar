# 蒙牛奶制品无人车配送平台企业版方案（简化版）

## 一、方案概述

### 业务背景

**客户定位**：
- 企业：蒙牛奶制品唐山分公司
- 业务：奶制品生产、仓储、配送
- 车辆规模：10-30辆无人车
- 自营网络：20-50个奶站（销售网点）

**配送网络**：

```
┌─────────────────────────────────────────────────────────┐
│                    配送网络                              │
├─────────────────────────────────────────────────────────┤
│                                                            │
│   [仓库/工厂]                                             │
│       (核心取货点/送货点)                                  │
│         ↕                                                  │
│   自营奶站（20-50个）                                      │
│   ├─ 路北万达店  ├─ 路南凤凰店  ├─ 丰润城西店             │
│   └─ ...                                                │
│         ↕                                                  │
│   商超/代理配送站（对外配送）                               │
│   ├─ 华润万家  ├─ 永辉超市  ├─ 丰润区代理站               │
│   └─ ...                                                │
│                                                            │
│   路线类型：                                                │
│   ① 仓库 → 多个奶站（批量配送）                           │
│   ② 仓库 → 多个商超（对外配送）                           │
│   ③ 奶站 → 仓库（调货回库）                               │
│   ④ 奶站 → 商超（调货到商超）                             │
│   ⑤ 自有车辆 → 外部订单（接单大厅）                       │
└─────────────────────────────────────────────────────────┘
```

### 核心需求

1. **一车多装**：一辆车装载多个配送点
2. **多装多卸**：多个取货点、多个送货点
3. **路径优化**：自动规划最优配送路线
4. **自有车辆对外服务**：闲置车辆接外部订单
5. **发布外部需求**：自有运力不足时让外部运力方接单
6. **小程序企业端**：与需求方、运力方界面风格保持一致

### 简化范围

- ❌ 不考虑配送员（使用无人车）
- ❌ 不考虑奶站管理员角色
- ❌ 不考虑仓库和奶站的库存管理
- ❌ 不考虑调货申请流程（调货作为普通配送需求处理）
- ❌ 不考虑调货算法（统一使用路径优化算法）
- ❌ 不考虑结算业务

## 二、角色与权限设计

### 角色定义

| 角色 | 职责 | 登录方式 |
|------|------|----------|
| 企业管理员 | 企业管理、车队管理、订单发布 | 小程序 |

## 三、核心业务场景

### 场景1：企业内部批量配送（仓库→多个奶站）

#### 业务背景

**适用场景**：
- 仓库批量配送到自营奶站
- 补货配送
- 配送频率：每日1-2次

**特点**：
- 单一取货点（仓库）
- 多个送货点（自营奶站）
- 使用自有车辆
- 批量配送（5-20个点）

#### 业务流程

```
企业管理员/调度员发布内部批量配送需求
  ↓
填写取货点
  ├─ 类型：仓库
  ├─ 名称：蒙牛奶制品唐山配送中心
  ├─ 联系人：王经理 138****1234
  └─ 地址：唐山市XX区XX路XX号
  ↓
添加多个送货点（奶站）
  ├─ 奶站1：路北万达店，地址XXX
  ├─ 奶站2：路南凤凰店，地址XXX
  ├─ 奶站3：丰润城西店，地址XXX
  └─ ...（可添加5-20个奶站）
  ↓
填写每个送货点的货物信息
  ├─ 奶站1：纯牛奶×20箱，酸奶×30箱
  ├─ 奶站2：纯牛奶×15箱，酸奶×25箱
  └─ 奶站3：纯牛奶×25箱，酸奶×20箱
  ↓
选择配送时间
  ├─ 期望时间：今天下午
  └─ 时间段：14:00-17:00
  ↓
系统自动计算
  ├─ 总重量：1800kg
  ├─ 总体积：3.6m³
  └─ 建议车辆：2辆中型车（载重1.5吨）
  ↓
提交需求，进入待调度
  ↓
调度员查看待调度需求
  ↓
系统自动路径优化
  ├─ 将送货点分配给车辆
  ├─ 优化每辆车的路线
  └─ 生成最优方案
  ↓
调度员确认方案
  ↓
无人车开始配送
  ↓
逐个奶站配送
  ↓
奶站扫码确认收货
  ↓
配送完成
```

```

  ↓

  ↓

  ├─ 商超1：纯牛奶×50箱，酸奶×40箱
  └─ ...
  ↓
选择配送时间
  ↓
选择运力来源
  ○ 仅自有车辆
  ● 自有车辆优先，不足时外部运力方补充
  ○ 仅外部运力方
  ↓

  ↓
提交需求
  ↓
系统智能分配
  ├─ 优先分配自有车辆
  └─ 自有车辆不足时，发布到外部平台
  ↓
生成配送方案
  ↓
调度员确认方案
  ↓
自有车辆路径优化
  ↓
外部运力方接单（如需要）
  ↓
开始配送
  ↓
配送完成
```

### 场景5：自有车辆接外部订单

#### 业务背景

**适用场景**：
- 企业自有车辆闲置
- 车辆利用率不足
- 希望增加收入

**特点**：
- 自有车辆进入公共接单大厅
- 接外部订单
- 收入归企业
- 不影响企业内部优先级

#### 业务流程

```
企业管理员查看车辆状态
  ↓
发现车辆M-001、M-002闲置
  ↓
企业管理员将车辆设置为"对外服务"状态
  ↓
车辆进入公共接单大厅
  ↓
外部需求方发布订单
  ↓
平台智能匹配
  ↓
推荐给车辆M-001
  ↓
企业管理员查看推荐
  ↓
评估是否影响内部配送
  ├─ 如果不影响：接单
  └─ 如果影响：拒绝
  ↓
选择接单
  ↓
确认接单
  ↓
系统路径优化
  ↓
开始配送
  ↓
配送完成
```

## 五、不影响现有系统设计

### 1. 数据隔离

**企业数据标识**：

```sql
-- 用户表扩展
ALTER TABLE users ADD COLUMN role_type VARCHAR(20);
-- role_type: 'merchant', 'owner', 'enterprise_admin', 'dispatcher'

-- 企业表
CREATE TABLE enterprises (
  id VARCHAR(36) PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  type VARCHAR(50), -- dairy, logistics
  status VARCHAR(20) DEFAULT 'active',
  created_at TIMESTAMP DEFAULT NOW()
);

-- 奶站表
CREATE TABLE dairy_stations (
  id VARCHAR(36) PRIMARY KEY,
  enterprise_id VARCHAR(36) NOT NULL,
  name VARCHAR(100) NOT NULL,
  address VARCHAR(200),
  location JSONB,
  created_at TIMESTAMP DEFAULT NOW(),
  FOREIGN KEY (enterprise_id) REFERENCES enterprises(id)
);

-- 企业配送需求表
CREATE TABLE enterprise_demands (
  id VARCHAR(36) PRIMARY KEY,
  enterprise_id VARCHAR(36) NOT NULL,
  pickup_point_type VARCHAR(20), -- warehouse, station
  pickup_point_info JSONB,
  delivery_points JSONB,
  cargo_info JSONB,
  time_window JSONB,
  vehicle_source VARCHAR(20), -- own, external, mixed
  status VARCHAR(20) DEFAULT 'pending',
  created_at TIMESTAMP DEFAULT NOW(),
  FOREIGN KEY (enterprise_id) REFERENCES enterprises(id)
);
```

**数据隔离原则**：
- 企业订单独立存储在 `enterprise_demands` 表
- 公共订单继续使用 `demands` 表
- 通过 `enterprise_id` 标识企业
- 不修改公共订单表结构

## 六、路径优化算法设计

### 1. 企业内部批量配送优化

**问题定义**：
- 1个取货点（仓库或奶站）
- n个送货点（奶站/商超，n=5-30）
- m辆车
- 每辆车载重C，容积V
- 找到最优车辆分配和路径

**算法流程**：

```
步骤1：取货点和送货点统一处理
  - 将取货点和送货点都作为配送节点
  - 取货点必须首先访问

步骤2：送货点聚类
  - 使用K-means算法，将送货点聚类为m组
  - 每组分配一辆车
  - 确保每组的总重量和总体积不超过车辆限制

步骤3：组内路径优化
  - 对每组使用遗传算法
  - 找到组内最优路径
  - 优化目标：最短距离 + 满足时间窗

步骤4：负载均衡
  - 检查各组的负载是否均衡
  - 如不均衡，调整分组

步骤5：最终优化
  - 使用模拟退火算法微调
  - 输出最优方案
```

### 2. 对外配送优化（自有+外部）

**问题定义**：
- 1个取货点
- n个送货点（商超/代理配送站，n=10-30）
- 自有车辆数量：m_own
- 外部运力方数量：不限
- 找到最优车辆分配

**算法流程**：

```
步骤1：优先分配自有车辆
  - 计算自有车辆能覆盖的送货点数
  - 优先分配自有车辆

步骤2：剩余点分配
  - 剩余送货点分配给外部运力方
  - 按距离和载重匹配

步骤3：路径优化
  - 自有车辆：内部算法优化
  - 外部运力方：各自优化

步骤4：协调时间
  - 确保所有车辆在时间窗内完成
  - 如有冲突，调整车辆分配
```

### 3. 单点配送优化

**问题定义**：
- 1个取货点
- 1个送货点
- 使用路径优化算法

**算法流程**：

```
步骤1：选择最近的空闲车辆
  - 计算距离
  - 选择最优车辆

步骤2：路径优化
  - 最短路径
```

## 七、车辆状态管理

### 车辆状态

| 状态 | 说明 | 可接订单 |
|------|------|----------|
| 空闲-内部 | 闲置，仅接企业内部订单 | 内部订单 |
| 空闲-对外 | 闲置，可接外部订单 | 内部+外部订单 |
| 执行-内部 | 正在执行企业内部订单 | 不可接单 |
| 执行-对外 | 正在执行外部订单 | 不可接单 |
| 维修中 | 车辆维修中 | 不可接单 |

### 状态切换逻辑

```
空闲-内部 → 空闲-对外：企业管理员切换
空闲-对外 → 空闲-内部：企业管理员切换
空闲-对外 → 执行-对外：接单后自动切换
执行-对外 → 空闲-对外：配送完成后自动切换
空闲-内部 → 执行-内部：接内部订单后自动切换
执行-内部 → 空闲-内部：配送完成后自动切换
```
