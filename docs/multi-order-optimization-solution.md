# 多场景订单合并与路径优化方案（完善版）

## 一、方案概述

### 业务场景定义

基于实际业务需求，定义4种核心场景：

| 场景 | 场景名称 | 触发方 | 关键特征 |
|------|----------|--------|----------|
| 场景1 | 大客户专属用车 | 需求方 | 多需求、一取货点、多送货点 |
| 场景2 | 推荐新单合并 | 平台 | 运力方已接单，智能推荐新单 |
| 场景3 | 智能筛选接单 | 运力方 | 接单大厅推荐组合，需洽谈 |
| 场景4 | 已谈单路径优化 | 运力方 | 多单已谈好，仅需路径优化 |

### 核心约束

**车辆锁定机制**：
- 车辆接单后立即锁定
- 完成所有配送并结算前，不能接其他订单
- 一车一单组（一个订单组合占用一辆车）
- 车辆释放后才可接新订单

**运费结算规则**：
- 场景1：按整单结算，运费协商确定
- 场景2：原单已结算，新单单独结算
- 场景3：每单单独结算，运力方与需求方洽谈
- 场景4：每单单独结算，总收益累加

## 二、场景详细设计

### 场景1：大客户专属用车服务

#### 业务背景

**适用场景**：
- 商家批量配送（如超市配送到多个门店）
- 企业多点配送（如公司配送到多个分部）
- 批发商送货（如仓库配送到多个客户）

**特点**：
- 同一取货点（仓库/门店）
- 多个送货点（分散在不同位置）
- 一次性发布多个需求
- 运费打包协商

#### 业务流程

```

  ├─ 送货点2：门店B，地址XXX，电话XXX
  ├─ 送货点3：门店C，地址XXX，电话XXX

  ↓

  ↓

  ↓

  ↓

  ↓

  ↓
运力方按路线执行配送
  ↓
逐个送货点送货
  ↓
所有送货点完成，车辆释放
```

#### 路径优化算法

**问题定义**：
- 一个取货点P
- n个送货点D1, D2, ..., Dn
- 找到最优路径：P → D(i1) → D(i2) → ... → D(in)
- 约束：在指定时间窗内完成

**算法选择**：
- n ≤ 10：TSP精确算法
- 10 < n ≤ 20：遗传算法
- n > 20：聚类+贪心算法

**优化目标**：
- 总行驶距离最短
- 总配送时间最短
- 满足时间窗约束
- 避免绕路

#### 特殊规则

**定价规则**：
- 批量订单打包定价，不是每单单独计费
- 建议定价 = 基础费 + 距离费 × 总距离 + 重量费 × 总重量
- 大客户可享受5%-10%的折扣

**时间窗约束**：
- 每个送货点可设置独立时间窗
- 算法必须满足所有时间窗
- 无法满足时，提示需求方调整

**车辆匹配**：
- 根据总重量、总体积推荐车型
- 只有匹配车型的运力方可接单
- 需要大车时，自动过滤小车运力

### 场景2：运力方已接单，平台推荐新单

#### 业务背景

**适用场景**：
- 运力方已有订单，车辆未满载
- 平台有新需求，与现有订单路线顺路
- 运力方可选择性接单，增加收益

**特点**：
- 运力方已有1-2单
- 新单与现有订单可合并
- 运力方有选择权
- 新单独立结算

#### 业务流程

```
运力方已接订单A
  ├─ 路线：A1 → A2
  ├─ 状态：已取货，配送中
  └─ 车辆：已锁定
  ↓
平台生成新需求B
  ├─ 取货点：B1
  ├─ 送货点：B2
  └─ 状态：待接单
  ↓
平台智能匹配算法运行
  ├─ 检查运力方当前位置
  ├─ 计算B1、B2与A1、A2的位置关系
  ├─ 评估合并可行性
  └─ 计算收益提升
  ↓
符合条件，触发推荐
  ↓
运力方收到推荐通知
  ├─ 推送消息：附近有顺路订单，增加50元收益
  └─ 显示订单详情
  ↓
运力方查看推荐订单
  ├─ 原订单A：路线A1→A2，收益80元
  ├─ 新订单B：路线B1→B2，收益50元
  ├─ 合并后路线：A1→B1→B2→A2
  ├─ 总收益：130元（增加50元）
  └─ 额外行驶：增加3km
  ↓
运力方选择：接单 或 忽略
  │
  ├─ 选择接单
  │   ↓
  │   运力方与新订单B的需求方洽谈运费
  │   ↓
  │   达成一致，确认接单
  │   ↓
  │   系统重新规划路径
  │   ↓
  │   更新配送顺序
  │   ↓
  │   按新路线执行
  │
  └─ 选择忽略
      ↓
      推荐失效，推荐给其他运力方
  ↓
所有配送完成
  ↓
分别结算订单A和订单B
  ↓
车辆释放
```

#### 智能匹配算法

**匹配条件**：

```
1. 位置条件：
   - 运力方当前位置到新取货点B1距离 ≤ 5km
   - B1、B2与现有路线的偏离度 ≤ 30%

2. 时间条件：
   - 新订单B的时间窗与现有订单兼容
   - 合并后所有订单不超过时间窗

3. 载重条件：
   - 车辆剩余载重 ≥ 新订单重量
   - 车辆剩余空间 ≥ 新订单体积

4. 收益条件：
   - 新订单收益 / 额外行驶距离 ≥ 10元/km
   - 总收益提升 ≥ 30%
```

**推荐评分**：

```
score = w1×位置得分 + w2×时间得分 + w3×载重得分 + w4×收益得分

位置得分：1 - (偏离距离 / 10km)
时间得分：1 - (时间延误 / 60分钟)
载重得分：1 - (新增重量 / 剩余载重)
收益得分：收益提升 / 预期收益

权重：w1=0.3, w2=0.3, w3=0.2, w4=0.2

score ≥ 0.7时才推荐
```

#### 推荐机制

**触发时机**：
- 新需求生成后，立即触发匹配
- 每1分钟轮询一次，检查运力方状态变化

**推荐方式**：
- 小程序：推送通知 + 红点提示
- H5：弹窗提示

**推荐优先级**：
- 评分最高的推荐给最近的运力方
- 如果运力方忽略，推荐给次优运力方
- 如果所有运力方都忽略，进入接单大厅

#### 特殊规则

**洽谈机制**：
- 运力方必须先与需求方洽谈运费
- 双方达成一致后才能接单
- 洽谈失败，推荐失效

**洽谈方式**：
- 电话联系
- 在线聊天（平台提供）
- 语音通话（平台提供）

**时间限制**：
- 推荐后15分钟内需确认
- 超时自动失效
- 防止占用订单资源

### 场景3：运力方智能筛选接单大厅

#### 业务背景

**适用场景**：
- 运力方空闲，主动寻找订单
- 一次性接多个订单，最大化收益
- 根据自己的偏好筛选订单

**特点**：
- 运力方主动选择
- 系统推荐最优组合
- 需要洽谈每单的运费
- 一车一单组，车辆锁定

#### 业务流程

```
运力方进入接单大厅
  ↓
设置筛选条件（可选）
  ├─ 区域：路北区
  ├─ 距离：5km内
  ├─ 重量：≤100kg
  ├─ 时间：今天
  └─ 订单数：3-5单
  ↓
系统推荐最优订单组合
  ├─ 组合1：3单，评分9.2分
  ├─ 组合2：4单，评分8.5分
  └─ 组合3：5单，评分7.8分
  ↓
运力方查看组合详情
  ↓
逐个洽谈订单的运费
  ├─ 订单1：与需求方1洽谈，确认运费
  ├─ 订单2：与需求方2洽谈，确认运费
  └─ 订单3：与需求方3洽谈，确认运费
  ↓
所有订单洽谈成功
  ↓
运力方确认接单组合
  ↓
系统规划最优路径
  ↓
车辆锁定
  ↓
按路径执行配送
  ↓
逐单结算
  ↓
车辆释放
```

#### 智能推荐算法

**组合生成**：

```
1. 按距离筛选：
   - 筛选出距离运力方5km内的订单
   - 得到候选订单集合C

2. 按载重筛选：
   - 筛选出载重匹配的订单
   - 更新候选集合C

3. 生成组合：
   - 从C中随机选择3个订单，生成组合1
   - 重复生成50个组合
   - 得到组合集合G

4. 评估组合：
   - 对每个组合g∈G，计算路径和收益
   - 计算评分score(g)

5. 排序推荐：
   - 按score降序排序
   - 取前5个推荐给运力方
```

**评分函数**：

```
score = w1×距离得分 + w2×载重得分 + w3×时间得分 + w4×收益得分

距离得分：1 - (总距离 / 20km)
载重得分：1 - (总重量 / 车辆载重)
时间得分：1 - (总时长 / 3小时)
收益得分：总收益 / 200元

权重：w1=0.25, w2=0.25, w3=0.25, w4=0.25
```

**推荐展示**：

```
组合1：3单（强烈推荐）
- 评分：9.2分
- 总收益：150元
- 总距离：12km
- 载重利用率：80%
- 预计时长：2小时

组合2：4单（推荐）
- 评分：8.5分
- 总收益：180元
- 总距离：15km
- 载重利用率：90%
- 预计时长：2.5小时

组合3：5单（一般）
- 评分：7.8分
- 总收益：200元
- 总距离：20km
- 载重利用率：95%
- 预计时长：3小时
```

#### 洽谈流程

**步骤1：选择订单组合**

## 三、通用机制设计

### 1. 车辆锁定机制

**锁定规则**：

| 车辆状态 | 说明 | 可操作 |
|----------|------|--------|
| 空闲 | 车辆未接订单 | 可接单、可转让 |
| 已锁定 | 车辆已接单 | 不可接单 |
| 配送中 | 车辆正在配送 | 不可接单 |
| 结算中 | 订单完成，正在结算 | 不可接单 |
| 已释放 | 结算完成 | 可接单、可转让 |

**锁定时间**：

```
接单时锁定 → 开始配送 → 完成配送 → 结算 → 释放
  ↓           ↓           ↓          ↓     ↓
  t0         t1          t2        t3    t4

锁定时长 = t4 - t0
```

**释放条件**：
- 所有订单完成
- 结算成功
- 无异常纠纷

**提前释放**（特殊情况）：
- 订单取消（双方协商一致）
- 车辆故障（需平台审批）
- 不可抗力（需平台审批）

### 2. 运费洽谈机制

**洽谈方式**：

| 方式 | 适用场景 | 优缺点 |
|------|----------|--------|
| 电话 | 快速沟通、复杂情况 | 优点：直接高效；缺点：无记录 |
| 在线聊天 | 简单沟通、有记录 | 优点：有聊天记录；缺点：响应慢 |
| 语音通话 | 平衡效率和记录 | 优点：有录音记录；缺点：需网络 |

**洽谈流程**：

```
发起洽谈 → 沟通协商 → 确认运费 → 记录运费 → 锁定运费
   ↓          ↓          ↓          ↓          ↓
  t0         t1         t2         t3         t4

洽谈时限 = 10分钟
```

**洽谈失败处理**：
- 超时未确认：订单释放，推荐给其他运力
- 洽谈不成功：移除订单，继续洽谈其他订单
- 运力方取消：订单释放，不影响其他订单

### 3. 路径优化算法通用框架

**算法选择策略**：

| 场景 | 订单数 | 算法 | 响应时间 |
|------|--------|------|----------|
| 场景1 | 1-20 | 遗传算法 | <2s |
| 场景2 | 2-3 | 贪心算法 | <100ms |
| 场景3 | 3-10 | 遗传算法 | <1s |
| 场景4 | 1-10 | TSP或遗传算法 | <2s |

**优化目标函数**：

```
minimize: α×总距离 + β×总时长 + γ×时间窗惩罚

约束：
- 先取货后送货
- 载重限制
- 时间窗限制
- 行驶距离 ≤ 1.5倍原距离

权重：α=0.4, β=0.3, γ=0.3
```

**实时优化触发**：
- 路况变化时重新规划（每5分钟）
- 订单变更时重新规划
- 运力方手动触发

### 4. 结算机制

**结算规则**：

| 场景 | 结算方式 | 结算时机 |
|------|----------|----------|
| 场景1 | 整单结算 | 所有配送点完成 |
| 场景2 | 分单结算 | 每单完成后立即结算 |
| 场景3 | 分单结算 | 每单完成后立即结算 |
| 场景4 | 分单结算 | 每单完成后立即结算 |

**结算流程**：

```
订单完成 → 确认收货 → 生成结算单 → 支付运费 → 到账
   ↓          ↓          ↓          ↓        ↓
  t1         t2         t3         t4       t5

结算周期 = t5 - t1
```

**运费分配**：
- 运力方：95%
- 平台：5%（服务费）

**异常处理**：
- 货物损坏：协商赔偿
- 配送延误：协商减免
- 拒收货物：协商处理

## 四、风险控制

### 1. 配送延误风险

**风险来源**：
- 路况拥堵
- 车辆故障
- 需求方取货延误
- 多订单合并导致时间冲突

**控制措施**：

```
1. 时间窗约束：
   - 需求方可设置时间窗
   - 算法必须满足时间窗
   - 无法满足时提示需求方

2. 实时监控：
   - 监控运力方位置
   - 预计延误超过10分钟，自动通知需求方
   - 预计延误超过30分钟，触发补偿机制

3. 补偿机制：
   - 延误30分钟：减免5元
   - 延误60分钟：减免10元
   - 延误超过90分钟：需求方可取消订单

4. 动态调整：
   - 实时路况变化，自动重新规划路径
   - 遇到拥堵，自动切换备选路径
```

### 2. 货物混乱风险

**风险来源**：
- 多订单货物混装
- 取货点错误
- 送货点错误

**控制措施**：

```
1. 货物标识：
   - 每个订单贴唯一二维码标签
   - 取货和送货时扫码确认

2. 分区装载：
   - 无人车设置多个储物格
   - 每个订单固定一个储物格
   - 按配送顺序装载

3. 扫码确认：
   - 取货时扫描需求方二维码
   - 送货时需求方扫描货物标签

4. 拍照留证：
   - 装车前拍照
   - 卸货前拍照
   - 发生纠纷时调取
```

### 3. 运力方违约风险

**风险来源**：
- 接单后取消
- 中途终止配送
- 不按时取货/送货

**控制措施**：

```
1. 信用体系：
   - 运力方信用评分
   - 违约降低评分
   - 评分过低限制接单

2. 保证金制度：
   - 运力方缴纳保证金
   - 违约时扣除保证金
   - 保证金用于赔偿需求方

3. 黑名单机制：
   - 严重违约列入黑名单
   - 永久禁止接单
   - 公开曝光

4. 实时监控：
   - 监控运力方行为
   - 异常行为预警
   - 及时干预
```

### 4. 运费纠纷风险

**风险来源**：
- 运力方临时加价
- 需求方拒绝支付
- 运费计算争议

**控制措施**：

```
1. 运费锁定：
   - 洽谈确认的运费锁定
   - 不得临时更改
   - 除非双方协商一致

2. 在线支付：
   - 推荐在线支付
   - 支付记录可查
   - 减少现金纠纷

3. 平台仲裁：
   - 发生纠纷，平台介入仲裁
   - 根据证据判定责任
   - 责任方承担损失

4. 费用透明：
   - 明确费用构成
   - 无隐藏收费
   - 提供费用明细
```
